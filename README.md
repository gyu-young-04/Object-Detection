# AI 기반 정리 가이드 어시스턴트 (웹)

경북대학교 전자공학부 설계프로젝트2 개인 프로젝트. 방 사진을 촬영하면 로컬(온디바이스) 모델이 정리 대상 물건을 탐지하고, 카테고리별 목적지와 정리 순서를 제안하는 웹 애플리케이션.

## 배경

1인가구 증가와 바쁜 현대인의 시간 부족으로 정리정돈에 어려움을 겪는 사람이 늘고 있다. 핵심 문제는 "정리가 불가능해서"가 아니라, 물건이 많을 때 반복되는 판단(결정 피로)과 "어디서부터 시작할지 모르는" 심리적 진입장벽이다. 모두에게 필수인 도구가 아니라, 물건 수가 많거나 시작을 못 하는 상황에서 유효한 도구로 스코프를 좁혀 설계했다.

## 핵심 기능

- 다각도 사진(3~5장) 업로드 → 오픈보캐뷸러리 모델 기반 물체 탐지 → 결과 합집합 통합
- 모드 선택: 전체 가이드 / 쓰레기만 / 영역 드래그 지정
- 카테고리 → 목적지 규칙 매핑 + 색깔 오버레이 + 이유 설명
- 클릭 기반 목적지 수정 (이번만 / 항상) → 유저별 예외 규칙 자동 저장
- 유저 정의 카테고리 등록 (텍스트로 설명 가능한 물건에 한정)
- 휴리스틱 기반 정리 순서 제안 (목적지 그룹핑 · 저노력 우선 · 밀집구역 우선)
- 라운드제 재촬영 (가려졌던 물건은 다음 라운드에서 자연스럽게 재탐지)

## 설계 원칙 (트레이드오프)

| 설계 지점 | 검토한 대안 | 최종 선택 |
|---|---|---|
| 어질러짐 판단 방식 | baseline 변화탐지 vs 카테고리 규칙 | 카테고리 규칙 (cold-start 문제 없음) |
| 다각도 사진 처리 | 정밀 재식별(re-id) vs 단순 합집합 | 단순 합집합 (IoU 병합, 실패해도 보수적으로만 작동) |
| 처리 위치 | 클라우드 API vs 로컬 오픈소스 모델 | 로컬 모델 (프라이버시·비용, 온디바이스 전환 가능하게 설계) |
| 탐지 카테고리 확보 | 커스텀 파인튜닝 vs 오픈보캐뷸러리 | 오픈보캐뷸러리 (학습 데이터 불필요) |
| 과거 위치 기억 | 인스턴스 재식별 vs 카테고리 개인화 | 카테고리 개인화 (동일 외형 구분 불가 한계) |
| 정리 순서 제시 | 3D 적재 순서 추론 vs 휴리스틱 정렬 | 휴리스틱 정렬 (단일 사진 리스크 회피) |

자세한 내용은 [`docs/plan.md`](docs/plan.md) 참고.

## 시스템 구조

```
다각도 사진 3~5장 입력
  -> 오픈보캐뷸러리 탐지 모델 (로컬)
  -> 탐지결과 합집합 통합 (IoU 병합)
  -> 카테고리 -> 목적지 규칙 테이블 (기본 규칙 + 유저 예외)
  -> 모드별 필터링 / 휴리스틱 정렬
  -> 색깔 오버레이 + 이유 설명 + 체크리스트 출력
  -> 클릭 수정(이번만 / 항상) -> 예외 DB 갱신
  -> 정리 진행 후 재촬영 (라운드 반복, 탐지 결과 없을 때까지)
```

- **플랫폼**: 웹앱 (네이티브 앱 대신 선택 — 탐지 모델과 같은 파이썬 생태계로 통합 부담이 적고, 배포 없이 브라우저로 바로 데모 가능)
- **처리 위치**: 사용자 본인 기기(로컬 서버)에서 처리, 외부 클라우드 미경유. 사용자별로 셀프 호스팅되는 구조라 개발자도 데이터에 접근할 수 없음
- **온디바이스 확장(스트레치)**: 모델 경량화(양자화) 후 라즈베리파이 등 임베디드 보드로 이식 시도
