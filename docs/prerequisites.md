# 구현 시작 전 사전 지식 정리

본격적인 구현(4주차~) 착수 전에 정리해두는 배경지식 / 시작 순서 / 작업 중 원칙 메모.

## 1. 필요한 배경지식

| 영역 | 필요한 이유 | 최소한 알아야 할 것 |
|---|---|---|
| 파이썬 기초 | 백엔드·모델 실행 전부 파이썬 | 변수, 함수, 조건문/반복문, 리스트/딕셔너리 |
| 웹 구조 개념 | 브라우저-서버 통신 이해 | 클라이언트-서버, HTTP 요청/응답, API 개념 |
| 백엔드 프레임워크 (Flask/FastAPI) | 사진 받아서 처리하는 서버 | 라우트(엔드포인트) 만들기, 요청 받기, JSON 응답 |
| 프론트엔드 기초 (HTML/CSS/JS) | 촬영 화면 · 오버레이 화면 | 기본 문법, 카메라 접근(`getUserMedia`), Canvas로 이미지 위에 그리기 |
| 이미지 처리 (Pillow) | 사진 전처리 | 이미지 열기/저장/크기조절 |
| 사전학습 모델 사용법 | 오픈보캐뷸러리 모델 실행 | pip 설치, 모델 다운로드 후 추론 실행 (Hugging Face 등) |
| SQLite | 유저 예외 규칙 저장 | 테이블 생성, 삽입, 조회 수준의 간단한 SQL |
| Git/GitHub | 버전 관리 | add/commit/push/pull, 브랜치 기본 흐름 |

깊게 알 필요는 없고, 감을 잡고 시작해서 필요할 때마다 찾아보는 방식으로 진행.

## 2. 시작 순서 (구현 착수 시 이 순서대로)

1. 파이썬 가상환경(venv) 세팅
2. **오픈보캐뷸러리 모델이 실제로 돌아가는지 최우선 검증** — 방 사진 한 장에 "옷", "쓰레기" 같은 텍스트 프롬프트로 탐지가 되는지 직접 확인 (전체 프로젝트의 핵심 리스크이므로 가장 먼저 확인)
3. Flask/FastAPI로 최소 동작하는 서버 하나 띄워보기
4. 브라우저에서 사진 업로드 → 서버 전송하는 최소 예제 구현

이 네 가지가 되면 이후 UI, DB, 개인화 로직은 그 위에 점진적으로 얹는 방식으로 진행.

## 3. 작업 중 기억할 원칙

- MVP를 우선하고, 온디바이스·PWA 같은 스트레치 목표는 핵심 파이프라인 완성 전에는 손대지 않는다.
- 설계 판단 근거를 그때그때 기록해둔다 (중간/결과발표 정리에 재사용).
- 기능 단위로 작게, 자주 커밋한다.
- 실측 데이터(정확도·속도)가 계획보다 우선한다 — 안 좋으면 `docs/plan.md`의 리스크 대응 전략을 적용한다.
- 막히면 기능을 줄이는 방향으로 판단한다 — 범위를 다 채우려다 미완성보다, 핵심만 확실히 완성하는 쪽을 우선한다.
